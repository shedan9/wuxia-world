# M3 多分辨率与画面比例核对

对应[开发计划 M3](../DEVELOPMENT_PLAN.md#m3第二阶段约-60-分钟玩法-demow11w16) 验收“同一场景在 1080p、1440p、4K 输出下检查清晰度、文字、遮挡和安全区，记录截图”与 6.1 T10“窗口比例变化”。规格见[架构文档 9.4.8](../ARCHITECTURE.md#948-m3-多分辨率与画面比例核对规格)。

## 1. 生成

| 项目 | 说明 |
|---|---|
| 前提 | 先运行 `./tools/scripts/export-windows.ps1` 生成导出包 |
| 全部 | `./tools/scripts/capture-play.ps1`：五种尺寸 × 14 个画面，另每种尺寸跑一次焦点与版式走查，约 25 分钟 |
| 部分 | `-Resolution 2560x1080 -Only 30` 只截 21:9 的剧情战；`-TextSize 32` 在最大正文字号下另存一套（目录名带 `-text32`）；`-NoFocus` 跳过焦点走查 |
| 输出 | `build/review/m3/<尺寸>/<编号_名称>.png` 与 `focus.txt`（本地产物，不入库）；存档写到临时目录，不碰玩家存档 |

尺寸：1920×1080、2560×1440、3840×2160（16:9）；1920×1200（16:10）；2560×1080（21:9）。4K 窗口在 4K 屏上截取，与全屏输出同尺寸。

## 3. 2026-10-04 结果

在本机（4K 144 Hz 屏）用导出包生成五种尺寸各 14 张截图，正文字号 20 与 32 各一套，逐张核对；焦点与版式走查五种尺寸、两种字号均为问题 0 处（17 页全部焦点可达、无死路、无越界或被裁掉的控件）。人物属性页在字号 32 时比外框高，按 M3-05 的做法可键盘滚动，截图里下半截在滚动区外属正常。

| 发现 | 尺寸 | 处理 |
|---|---|---|
| 剧情战两军整体偏左，右侧空出一大块 | 21:9 | 场上层水平居中（`BattleScreen.CenterField`） |
| 导出包里中文只能在空格处折行：第一个选项的序号“1”单独占一行 | 全部（只在导出包） | 导出包带上文本服务器断行数据（`include_text_server_data`） |
| 第一章最长选项折出一个字（“所有／人。”） | 全部 | 选项栏 740 → 820 宽 |
| 队伍页空格的格名写在下一格人物肩旁；底部提示压在左下角卷云上 | 全部 | 空格名只在换位、悬停或焦点时写出；提示行左缩 |
| 瞬移走查的探索截图里看不到主角 | 全部（只在开发工具） | 走查把主角与同行者放在同一点，主角被挡住；核对脚本改用真实行走 |
| 正文字号 32 时人物画框底部名签“全身样稿　立绘待制作”被画框裁掉半行（人物页、队伍页） | 全部 | 名签向上长；焦点走查加“被外层裁切容器剪掉”的检查，此前查不出 |
| 正文字号 32 时队伍页底部操作提示只露半行 | 全部 | 阵位规则说明移到右栏底部 |

未发现问题的：16:10 下各页（画布增高，指令区、对话框贴底，人物与菜单不拉伸）；21:9 下探索、对话、菜单、大地图、章终（四角界面贴边，中间给场景）；4K 下界面笔触、文字与人物边缘清晰，未见放大低清画面的糊边。

未做：4:3 等窄于 16:10 的比例；Windows 显示缩放（高 DPI）下的窗口模式；用户本人在实际显示器上的观感确认。
